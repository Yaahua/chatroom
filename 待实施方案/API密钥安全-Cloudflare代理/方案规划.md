# API 密钥安全方案：Cloudflare Worker 代理

> **状态**：待实施（已备好代码，随时可部署）
> **优先级**：低（当前为小范围私用，暂不紧急）
> **预计工时**：15 分钟

---

## 背景与问题

当前 DeepSeek API Key 硬编码在 `src/useAI.ts` 第 6 行，会被 Vite 打包进 `dist/` 的 JS bundle 中。任何人通过浏览器 DevTools 或直接下载 JS 文件即可获取明文密钥。

---

## 方案概述

在前端与 DeepSeek API 之间插入一个 **Cloudflare Worker** 作为代理层：

```
浏览器 → Cloudflare Worker（持有 Key） → DeepSeek API
```

- 前端只知道 Worker 的公开 URL，不持有任何密钥
- API Key 存储在 Cloudflare Worker 的 **Secret 环境变量**中，不出现在任何代码或 Git 历史里
- Worker 免费额度：每天 10 万次请求，完全够用

## 实施步骤

### 第一步：部署 Cloudflare Worker

1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com)
2. 进入 **Workers & Pages** → **创建应用程序** → **创建 Worker**
3. Worker 名称填 `chatroom-deepseek-proxy`（或任意名称）
4. 将 `index.js` 的内容粘贴到编辑器，点击**部署**
5. 记录 Worker 的访问地址，格式为：
   ```
   https://chatroom-deepseek-proxy.<你的子域名>.workers.dev
   ```

### 第二步：配置 Secret 环境变量

在 Worker 详情页 → **设置** → **变量和机密** → **添加机密**：

| 变量名 | 值 |
|--------|----|
| `DEEPSEEK_API_KEY` | `sk-209a9d7b033b45b685c3ce767521a802` |
| `ALLOWED_ORIGIN` | `https://你的GitHub用户名.github.io`（可选，留空则允许所有来源） |

### 第三步：修改前端代码

编辑 `src/useAI.ts`，将：

```ts
const DEEPSEEK_API_URL = 'https://api.deepseek.com/v1/chat/completions'
const DEEPSEEK_API_KEY = 'sk-209a9d7b033b45b685c3ce767521a802'
```

替换为：

```ts
const DEEPSEEK_API_URL = 'https://chatroom-deepseek-proxy.<你的子域名>.workers.dev/v1/chat/completions'
```

同时将 `fetch` 调用的 `headers` 中移除 `Authorization` 字段（Key 由 Worker 注入，前端不传）：

```ts
headers: {
  'Content-Type': 'application/json',
  // 不再传 Authorization，Worker 会自动注入
},
```

### 第四步：构建验证并推送

```bash
pnpm build && pnpm lint
git add -A && git commit -m "feat: 接入 Cloudflare Worker 代理，移除前端硬编码 API Key"
git push
```

---

## 注意事项

- Worker 免费版有每日 10 万次请求限制，小范围使用绝对够用
- 如果 `ALLOWED_ORIGIN` 填了具体域名，其他来源（如本地 `localhost`）调试时会被 CORS 拦截，可临时留空或加白名单
- 部署后原来的 Key 已暴露，建议在 [DeepSeek 控制台](https://platform.deepseek.com) 重新生成一个新 Key 填入 Worker Secret
